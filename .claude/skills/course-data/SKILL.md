# Course data pipeline (`tools/course/`)

Python venv `~/.venvs/galena` (numpy, scipy, rasterio, pyproj, shapely, pillow, laspy[lazrs], scikit-image, requests, pyflakes). Run from `tools/course/`; `pyflakes *.py courses/*/course.py` must stay clean. Frame: local transverse Mercator in metres around the course's `ORIGIN`.

**One folder per course.** `tools/course/courses/<key>/` holds `course.py` (name, origin, OSM way of the course outline, areas, elevation sources, highway and side roads, scorecard, tee-marker sets), `.cache/` (downloads) and `out/` (the painted masks and every generated file). `.cache/` and `out/` are git-ignored and live only on this machine: never delete them. Every script works on one course, picked with `--course <key>` (taken out of `sys.argv` by `common.py`, so the scripts' own arguments are unchanged) or `GALENA_COURSE`; `woodbine` when neither is given. `common.py` gives the scripts `KEY`, `course` (the loaded `course.py`), `OUT`, `cache()`, `RD_JS` and `load_rd()`. The raw sound recordings are not per course: `tools/course/sounds_raw/` (git-ignored), read by `sounds_trim.py`. In the tables and steps below, `out/` and `.cache/` mean the course's own folders.

1. Geodata (re-run only if needed): `fetch.py` (OSM via Overpass with a `User-Agent`, NAIP aerial 0.5 m, USGS 1 m DEM), `lidar.py` (canopy model from the 2019 lidar), `trace.py` (first-pass fairways; still the base map for fairway painting), `trees.py` (lidar trees), `creek.py` (creek centre line from the DEM channel; `creek.py osm` takes the OSM streams instead, as at Eagle Ridge South). Where OSM maps fairways (Eagle Ridge), `build.py` uses them unless `fairways_painted.json` exists; OSM ponds tagged only `golf=water_hazard` count as water (`osm.py`), and with `OSM_WAY` set only golf features near that course's outline are kept.
2. Painted layers: the user paints a copy of a generated map and saves a PNG (solid colours, hard edges, never resized or cropped); a reader script turns it into polygons. All maps share the pixel grid of `fescue_base.json` except trees and creek, which have their own frame JSON.

| Layer | Make the map | User saves | Reader (output in `out/`) | Colour |
|---|---|---|---|---|
| fescue (deep rough) | `fescue_base.py` | `fescue_mask.png` | `fescue.py` → `fescue.json` | magenta `#FF00FF` |
| course boundary (OB) | `fescue_base.png` | `course_boundary.png` | `boundary.py` → `boundary.json` | cyan `#00FFFF` |
| fairways | `fairway_edit.py` | `fairway_mask.png` | `fairways.py` → `fairways_painted.json` | green `#00FF00` |
| bunkers | `bunkers_edit.py` | `bunkers_mask.png` | `bunkers_paint.py` → `bunkers_painted.json` | orange `#FF8000` |
| trees | `trees_edit.py` | `trees_mask.png` | `trees_paint.py` → `trees_painted.json` | orange broadleaf, blue `#0080FF` conifer, magenta shrub |
| creek | `creek_edit.py` | `creek_mask.png` | `creek_paint.py` → `creek_painted.json` | blue `#0000FF` |
| site props | `site_edit.py` | `site_mask.png` + `signs.txt` | `site_paint.py` → `site_props.json` | cyan washroom, blue door strip, orange porta-potty, yellow sign, violet `#8000FF` parking lot (the OSM outline is drawn as a guide; `lot_rows` lays out the stalls along the nearest building and parks `CARS` = 8 cars, seeded, in `CAR_LOOKS` models and colours) |
| tee boxes + entrance sign + shed | `paint_edit.py` (whole course and US 20, 4 px per metre) | `paint_mask.png` | `paint_read.py` → `tees_painted.json` (every box must be painted; `--keep` keeps unpainted ones), `tee_starts.json`, `paint_props.json` (site_paint.py adds it to `site_props.json`) | magenta tee boxes, yellow played-tee dots, purple rectangle (entrance sign + flower bed), optional blue strip on its lettering side (default: facing the course), orange rectangle = a shed (pump house) |
| practice green | `practice_edit.py` (8 px per metre, around it) | `practice_mask.png` | `practice_read.py` → `practice.json` (green, bunkers, fescue, cups, trees; `build.py` adds them: the green joins `feat.green`, the painted fescue is merged into the course's by `merge_fescue`, the scene is `RD.prac` and its 1 m lattice `GREEN_ALTI.prac`) | green `#00FF00`, fringe cyan (guide only, the game cuts a 1.5 m collar), fescue magenta (edges that run off the map continue into the course's fescue), orange bunkers, red dots = the four cups, yellow dot = one broadleaf tree as wide as the dot |
| driving range | `range_edit.py` (5 px per metre; also writes `range_start.png`, the OSM range outline filled green, to paint on) | `range_mask.png` | `range_read.py` → `range.json` (`build.py` makes `RD.drv`: its own polygons and boundary, the spots, the flags nearest first, the trees, and a `shed` row added to `props`) | green mown grass, cyan target greens, magenta fescue, orange bunkers, blue dots = hitting spots, red dots = flags, yellow circles = trees (touching ones are split), azure `#0080FF` = a long metal shed |
| cart paths | `cartpaths_edit.py` (finds them on the aerial: pale grey, thin; yellow guide on a 3 px per metre map) | `cartpaths_mask.png` (optional) | `cartpaths_read.py` → `cartpaths.json` (the network traced into lines, each smoothed along its length with junctions held, then drawn 2.4 m wide; `build.py` encodes them as `feat.path`, the game's asphalt `S.PATH`) | red `#FF0000` = a missing path (any brush width), blue `#0000FF` = remove what was found there |
| tee boxes, whole course (shelved) | `tee_boxes_edit.py` | `tee_boxes_mask.png` | `tee_boxes_paint.py` → `tees_painted.json`, `tee_starts.json` | magenta boxes, yellow start dots |

   `bunkers_auto.py` found six bunkers OSM lacks (`bunkers_auto.json`); `bunkers_painted.json` replaces OSM and auto bunkers when present. Signs: `signs.txt` lines like `7: LINE ONE | LINE TWO`; a yellow dot whose nearest hole has no line is not built.
3. `build.py` encodes everything into `out/rd_<key>.js` (`const RD_<KEY>` and `const GREEN_ALTI_<KEY>`); it prefers painted files over generated ones, clips fescue to the boundary, links each hole's fairway to its green by convex hull (`link_fairways`, so no gap of rough), and snaps the four tee sets (`course.MARKERS`: slot `w` is the set played; at Woodbine gold, then black, silver, bronze) to the tee boxes at their card yardages.
4. `install.py` writes the game's file `courses/<key>.js` (repo root; `COURSE_DATA.<key>.rd` and `.alti`). Then a headless run.

The outlines are smoothed so painted pixel staircases do not show: `bunkers_paint.py`, `fairways.py` and `fescue.py` trace the sub-pixel contour of the blurred mask (`smooth_polys` in `common.py`; blur `SMOOTH` px, `TOL` m simplification, area kept within about 1%), and `paint_read.py` does the same for the painted tee boxes, and `build.py` rounds the OSM green outlines (`round_green`, Chaikin corner cutting), the OSM pond outlines (`round_pond`: the same, scaled back to the original area) and the creek's centre line (`round_line`, ends fixed) before it is cut into ribbons; `creek_paint.py` traces a painted creek mask with `smooth_polys` too. Outlines taken straight from OSM with nothing painted over them (Eagle Ridge South's fairways, bunkers, tees and course outline) go through `round_osm` (the same corner cutting on every ring, grown back to the original area by an even offset; the outline is first given a point every 12 m so only its corners round), OSM fairways get a 5 m closing after `link_fairways` so the joins to the greens have no kinks, and `ROUND_ROADS = True` in a course.py rounds its side roads with `round_line`. The raw pre-smoothing JSON is kept beside each (`*_raw_backup.json`).

To change a layer: repaint the mask, run its reader, then `build.py` and `install.py`.

The highway (`course.HIGHWAY`; at Woodbine US 20; `highway` and `hwSlow` in the data, empty when the course has none) is not painted: `build.py highway()` reads it from `.cache/osm.json` (clipped to the 2 m class grid, west to east; `hwSlow` is the distance along it where the limit drops to 35 mph). It reads the raw file because `osm.load` loses ways that Overpass lists twice (the second copy has no tags), which includes both US 20 ways.

# Adding another course

Everything a course needs is data; no code changes in `index.html`, the leaderboard workflow or `tools/players/stats.py`.

1. **Tools.** Copy `tools/course/courses/woodbine/course.py` to `tools/course/courses/<key>/course.py` (the key is short, lower case, letters, digits and `_`; it names files, storage keys and the multiplayer lobby, so never change it once rounds are posted) and fill it in: name, origin, `OSM_WAY` of its `leisure=golf_course` outline (with it set, `osm.load` keeps only that course's outline and the holes inside it, so a resort's other courses can share the download), the areas, the USGS DEM and lidar project names, the highway (`None` for none) and side roads, the scorecard and `MARKERS` (which tee set is played).
2. **Data.** Run the pipeline above with `--course <key>`: `fetch.py`, `lidar.py`, `trees.py`, then paint and read the layers it needs, then `build.py` and `install.py`, which writes the game's `courses/<key>.js`. A course has 18 holes (the workflow and the stats take 18).
3. **List it.** Add an entry to `courses/courses.json`: `key`, `name`, `short` (the course picker and the multiplayer list), `pars` (must match the data: the game warns in the console if not; the workflow takes the round's par from them), `recFrom` (launch day, `YYYY-MM-DD`: records count from then), `about` (the help sheet's course text: tees played and data credits), `engine` (at least `fescue` and the class grid `gr`, which must cover the holes), `scene` (its own scenery, all optional: `clubhouse`, `parkedCarts`, `turkeys`, `cartRide`, `hotdogHole`, `fountainHole`, `songs`; see **Courses** in CLAUDE.md). The list's order is the picker's; the picker appears once there are two courses.
4. **Describe it.** Add its section to part 2 of `on_course_objects.txt`.
5. **Test** headless: pick it, all 18 holes in bounds, a shot, no page errors; then the practice green and range from it (they switch to Woodbine's data and back). Commit `courses/<key>.js`, `courses/courses.json`, `tools/course/courses/<key>/course.py` and `on_course_objects.txt` (its `out/` and `.cache/` stay on this machine). The leaderboard and records files appear with the first posted round.
