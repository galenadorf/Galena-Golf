# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

**Galena!!! Golf**: a mobile, browser-based 3D golf game (installable PWA), forked from SweetSpot (https://github.com/nephlonor/SweetSpot). It has exactly one course, **Woodbine Bend Golf Course** (Stockton IL), built from public geodata. Repo: https://github.com/galenadorf/Galena-Golf, branch `main`, live at https://galenadorf.github.io/Galena-Golf/.

**v1.0 (major milestone):** build `ce4c23d`, 2026-10-27 16:30 CDT (21:30 UTC), the commit that turned PALS Rules on by default. This is the first version of the game considered complete (also noted in `README.md`).

## Ground rules

- **Offline rule.** Solo play must work fully offline with no CDN or third-party dependency. Everything the game needs lives in the repo and `sw.js` caches it. Only live multiplayer (public MQTT brokers), the world leaderboard and the Player ID roster (GitHub API, `raw.githubusercontent.com`) may use the network, and they must fail quietly offline. Never add an external script, font or asset: download it into `vendor/` or `fonts/` with its licence and add it to `CORE` in `sw.js`. Sounds are synthesised, embedded as base64, or short MP3 files in `sounds/` (trimmed by `tools/course/sounds_trim.py` from the raw recordings in `out/sounds/`; listed in `CORE` in `sw.js` and copied by `pages.yml`).
- **Units.** The UI shows yards (feet on and around the green, mph for wind and ball speed). The engine works in metres. `CLUBS[].carry` is in metres.
- **`on_course_objects.txt`** (repo root) lists everything a player can see on the course: animals, aircraft, weather, scenery and man-made objects, with how often each appears. Keep it current-state only. Whenever you add, remove or retune an object (animals, planes, props, signs, buildings, markers, weather) or change how often it appears, update that file in the same change, and delete entries for things that are gone.
- **Battery.** Phones drain fast, so the render loop is throttled by default: `frameGap()` runs the scene at `REST_FPS` (40) on the title screen and while standing over the ball (full rate for the flyover, swings, flight and any touch in the last 0.7 s), the shadow map redraws only when its view moves or every 0.1 s (`shadowMap.autoUpdate = false`), the renderer's pixel ratio is capped at 1.5, and the three HUD canvases redraw at 15 fps at rest (10 fps while the ball is away). Keep new per-frame work inside those limits.
- **Git.** Commit and push only when the user asks. `git add -A` skips `tools/course/out/` (ignored), so add paths explicitly and check `git status` after a commit. One commit usually covers `index.html` plus the tools, because they can't be split.
- **The painted masks are not in git.** `tools/course/out/` and `.cache/` are git-ignored, so the user's hand-painted masks (`*_mask.png`, `signs.txt`) and every generated JSON live only on this machine. The game does not need them to run (their results are embedded in `index.html`), but they are the source of truth for the course data. Never delete `out/`; tell the user if you change how they are used.

## Working with index.html

`index.html` is the whole game: HTML, CSS and JS in one file (about 5,900 lines, 0.9 MB), no build step. Three lines are huge embedded data; never print them whole, use `cut -c1-200`: `RD_WOODBINE` (course data, ~295 KB) and `GREEN_ALTI_WOODBINE` are **written by `tools/course/install.py`, never edit by hand**; `SND_B64` (base64 MP3) and `CLUB_SPR` (base64 WebP) are static.

- Edit with small Python scripts that assert each `old` string matches exactly once. Line numbers drift constantly: find things with `grep -n` on the function or constant name. Code is organised under `/* ===== NAME ===== */` banners: UTIL, PHYSICS, REAL COURSE, WORLD (three.js), GAME, UI, STATS + RECORDS, PLAYER + LEADERBOARD, INPUT + LOOP.
- Python offsets are code points but JS/node offsets are UTF-16, and the file contains non-BMP characters. Never apply node-computed offsets from Python; do the splice in node or work by string match.
- **Check JS** after every edit: write the text between the last `<script>` and its `</script>` to a scratch file (`s[s.rfind('<script>')+8 : s.find('</script>', s.rfind('<script>'))]` in Python) and run `node --check` on it. For unused or undefined names, run ESLint (`no-undef`, `no-unused-vars`) on that same file from a scratch folder.
- **Browser testing (WSL, no system browser).** In a scratch folder: `npm i playwright@1.48.2 && npx playwright install chromium`; Chromium lacks `libnss3`, `libnspr4`, `libasound2t64` and there is no sudo, so `apt-get download` them, `dpkg-deb -x <deb> <dir>`, and run node with `LD_LIBRARY_PATH=<dir>/usr/lib/x86_64-linux-gnu`. Serve the repo with `python3 -m http.server` and launch with `--use-gl=swiftshader --enable-unsafe-swiftshader --no-sandbox`. Fill `#nameIn`, click `#btnPlay`, then drive the game through globals (`startHole(i)`, `G`, `W`, `impact()`, `simulateShot()`; overriding `updateCamera = () => {...}` gives a fixed camera for screenshots). Swiftshader is slow, so game time runs well under real time. There is no test suite; "tested" means all 18 holes load with every tee and cup in bounds, a shot plays, and the page logs no errors (MQTT WebSocket errors are expected offline).
- `.github/workflows/pages.yml` deploys on push to `main`: copies `index.html manifest.webmanifest sw.js *.png icon.svg vendor fonts`, replaces `__BUILD__` with the commit SHA in `index.html` and `sw.js`, writes `version.txt` (the running game reloads itself when it changes). `sw.js` is network-first for the page (cache after 4 s), cache-first otherwise, cache name `galena-<BUILD>`; it needs https or localhost.
- `.github/workflows/leaderboard.yml`: registered players post scores as issues titled `[score] ...` whose JSON body is `{msg, sig, key}` (the round, signed by a device key); the workflow checks the signature against `players.json`, validates the round and its 18 per-hole rows, appends to `leaderboard/<course>.json` (the best 500 rounds plus every round of the last 46 days; the game shows the top 40 plus anyone tied with 40th for "All time" or "Last 45 days"; equal to-par scores share a rank, shown T4, T4, then 6; after a registered player's round posts, the "Round posted" pill says "You're #4 on the leaderboard" (`worldPlace`, T4 when tied); a round is its player ID and time, so equal scores are fine; at most 15 rounds a day per player) `rounds/<id>/<year>.json` (every round of that player with its per-hole data, one small file per UTC year) and `stats/<id>.json` (their lifetime summary: per course the rounds, best round and per-hole running totals, a constant size; `tools/players/stats.py` rebuilds it from the year files, splits any flat `rounds/<id>.json`, and with `--backfill` files the leaderboard rounds a player's year files lack, with `hs: null` because they were played before per-hole data; such a round counts as a round and for the best round only), and closes the issue. Its `COURSES` map is course key to par (`woodbine: 72`). **Records** belong to the account, per course, and count only for a registered player's full 18-hole round (nothing from practice, nothing per device). The signed round (message version 3) carries `x` = `{d: drive, h: holed shot, p: holed putt}`, each `[decimetres, hole]`, plus `l` = the round's lipped-out putts (a count: putts with a `lip` event that did not drop), collected in `G.xr` by `statsShot` (saved with the round) and plausibility-checked by the workflow; the other records (fewest and most putts, best nine, birdies, greens, fairways and their streaks within a round) are worked out from the 18 hole rows (`roundMarks` in index.html, the same rules in the workflow and in `tools/players/stats.py`). The workflow keeps each player's bests in `stats/<id>.json` (`courses.<c>.rec`: key -> `[value, hole, at]`) and the top 5 players of each in `records/<course>.json`; `stats.py` rebuilds both (only rounds from 2026-10-27 on, `REC_FROM`). The Stats sheet shows my bests beside the world's (`recs`, `loadRecords`), the leaderboard sheet has a Rounds | Records switch (`fillRecords`: every record of the course with its holder, a tap opens the top 5), `recWatch`/`recNoticeFlush` show a "Record beaten" card at the title screen when someone takes a record I held (the ones I hold are remembered in localStorage `ssg-recheld`), and `recCheck` shows New personal / world record cards when a round ends. Adding a course: add its pars to `PARS` in the workflow and in `stats.py`. Score posting points at `GH_REPO`; `GH_POST_KEY` holds an embedded post-only token (obfuscated) so scores post without a GitHub account (the signature, not the token, says who posted). `_original/` (git-ignored) is an untouched copy of the fork, for reference.
- **Player ID** (`PID`, `pidInit`/`pidSync`/`signRound` in index.html, just above `postAuto`; roster `players.json` at the repo root; admin tool `tools/players/players.py`). `players.json` is `[{id: "P007", name, keys: [{k, label}]}]`, written only by the admin. Each device makes its own ECDSA P-256 key pair on first use (private JWK in localStorage `ssg-pid`; never leaves the device) and files an ID request as a `[register]` issue (Settings > Player ID > Request ID; Copy ID request gives a `GG1-...` code as a spare); the admin approves it in GitHub (Actions > Approve player, `approve.yml`, run by hand with the issue number and `new` or an existing ID, so only repo writers can) or with `players.py pending|approve`, and uses `players.py add|device|drop|rename` for the rest. A device whose public key is in the roster is registered (`isReg()`): its name is the roster's, its rounds are signed and posted, per-hole history (the filed `stats/<id>.json` plus this device's newer unfiled rounds from `ssg-hist`) is shown on the Hole by hole page (Stats > Hole by hole: a bar chart of the last 45 round totals against par from `rounds/<id>/<year>.json`, then per hole par, length, best, average and an eagle / birdie / par / bogey / double split bar from the summary's per-hole stroke histogram; `holeAgg`, `openHoles` in index.html). Any other device is a guest: solo play and local stats only, nothing posted. The game reads `players.json` from raw.githubusercontent.com (cached offline in `ssg-reg`); revoking a key turns that device back into a guest. Not gated yet: multiplayer rooms (still open to guests).

## Architecture

**Data to game.** `tools/course/` (Python) turns public geodata into one data object, `RD_WOODBINE`, that `install.py` splices into `index.html`. At run time: `setCourse` (`COURSES`, `RDS`, `WOODBINE_DEFS`) selects it; `realPrep` decodes the course-wide data once (`GC`); `makeRealCourse(idx, pin)` builds one hole as a lattice of fields (fairway, green, tee, sand, water, creek, fescue distance fields) plus the ground height, dug greens, ponds, bunkers and creek pieces, and returns the `C` object the whole game uses (`C.surf`, `C.h`, `C.wl`, `C.cup`, `C.treeHit`); `buildRealHole` makes the three.js scene (terrain shader, trees, buildings, props, wildlife). The LiDAR relief layer (mounds) is added over the whole ground except on greens (`GM` mask in `makeRealCourse`): each green already carries the real contours, and counting them twice made hole 7 average a 9 % grade (a ball never slows above `mu` = 5.6 %). Surface class is decided in `surfInfo` in a fixed precedence (water, sand, green, fringe, tee, path, fairway, first cut, deep, rough); the tall fescue is the only `DEEP`. Water is judged by the water level over the ground: inside the painted outline anything 2 cm under counts, outside it (the dug banks dip below the water line) a ball is wet once the water covers half of the drawn ball (`WET_HALF`), so a ball visibly in the water is never a playable lie. Everything outside the hand-painted boundary is out of bounds.

**Ball flight.** `simulateShot(C, o)` is a fixed-step simulation (drag, lift and spin fitted to TrackMan data; surface bounce, roll, trees, buildings, cup). `calibrateClubs()` solves each club's ball speed at start-up so a full swing on flat ground carries exactly `CLUBS[].carry`; `launch` and `spin` shape the flight and roll, `smash` only sets the displayed clubhead speed. `impact()` turns the swing (`SW`: tempo, strike dot) into a launch, runs the simulation, and `updateFlight(dt)` plays the recorded frames back with the camera (`camFollowTargets`), trail, particles and slow-motion. A pure, full-speed, well-timed strike with a sand or lob wedge (`pure` in `computeLaunch`; `WEDGE_SPIN`) carries `biteSpin`, extra spin used only at the first landing (`o.bs` in `simulateShot`), so it checks and backs up a few yards on a green while the flight and the calibrated carry stay as they are; a tailwind removes the spin-back (`TAIL_NO_BACKSPIN`). The "Dramatic bounce" setting (`drama()`, `HOP_K`, `BALL_CAP`) only changes how the flight is drawn, never the physics.

**Practice green.** A scene beside the 18 holes (`RD.prac`, `PRAC`/`PRAC_DEF`, `makeRealCourse(PRAC)`; data from `tools/course/practice_read.py`, see the `course-data` skill), reached from the Practice menu (`startPuttingGreen`, `G.pg`, `body.pg`). It has four cups (`C.cups`; `C.cup` is the one aimed at; `simulateShot` judges the ball against the nearest, `res.cup` is the one it fell in), all four flags stay up, and a close map (`C.planBox`) on which a tap puts the ball down (`mapPick`). `pgFinish` replaces `finishShot` there: every putt or chip counts, a holed ball is set 2 ft from its cup, `#pgBar` offers the cup to aim at and Redo (back to where the last shot was played from). The counter is for the session only; nothing is scored, saved or awarded (`finishShot` returns to `pgFinish` before `statsShot`).

**Driving range.** A second practice scene (`RD.drv`, `RANGE`/`RANGE_DEF`, `makeRealCourse(RANGE)`; data from `tools/course/range_read.py`, mask `out/range_mask.png` painted over `range_edit.py`'s `range_edit.png`/`range_start.png`: green mown grass, cyan target greens, magenta fescue, orange bunkers, blue dots hitting spots, red dots flags, yellow circles trees, azure `#0080FF` the metal shed). It rides on the practice-green plumbing: `G.pg` with `range: true` (`startPuttingGreen(true)`, `body.pg` + `body.rg`, `#pgBar`: the Flag button is `pgCup`, the Spot button is `pgRe`). The painted features and boundary live only in `RD.drv.feat`/`.boundary` (`rangeScene`), never in the course-wide `feat`, so no hole sees them; the shed is a `shed` row appended to `props`. Flags are `C.cups` with `C.noCup = true` (no hole, no holing, taller poles); `rgAim` aims at the chosen flag without touching the club, `rgPlace` stands on a spot (teed unless in sand), `rgFinish` shows carry/total/to-flag, rests the camera ~1.4 s, then `rgPlace` + `settle` bring it back (no early arrival move: `canPre` is off on the range). A spot on unpainted ground gets 5 m of mown grass and is kept in bounds by `range_read.py`.

**PALS Rules** (Settings, on by default since v1.0; `palsV` 3 switched every device on once, `pals()`): house rules, so far the **mulligan**: one per nine holes (`G.mull`, use it or lose it), taken at address on the shot just played (`mulliganOk`, `mulligan`; not after holing out; a penalty stroke goes with it). `impact` snapshots the state (`G.snap`: strokes, putts, flags, the round's shot records, the stats counters, the lie, club and aim) and a mulligan restores it; the button sits over the tempo bar and needs a second tap. The signed round carries `mu` (1-2, only when taken), the workflow keeps it on the leaderboard row and the board shows "mulligan". Rounds with mulligans stay on the board and count for records. The **maximum hole score** (`maxScore(par)`): par + 5 normally, double par + 1 with PALS Rules on (par 3: 7, par 4: 9, par 5: 11); a hole that reaches it is picked up. The **gimme**: a ball at rest on the green or fringe inside 24 in (`GIMME_M`) of the hole is conceded in `finishShot`: one stroke and one putt are added, the hole ends, and a brown "Inside the rope!" card (`gimmeCard`, `gimmeRope`: an SVG of a 22 in length of teal, yellow and red braided rope, to scale) shows. Not recorded in the signed round.

**Round state.** `G` holds the round (scores, putts, `G.pins`, weather); `saveRound` persists it per course; each round takes the day's pin (0-3: front, back, right, left, as seen on the way in) per hole from `pinSheet()`: a hash of the pin day (Central time, rolls over at 5:00 AM), the course, the private room code (or `open` for solo and the public lobby) and the hole, so everyone in the same lobby plays the same pins. A round keeps its pins once started; practice still draws random pins.

**Tunables worth knowing:** `HW_FAST`/`HW_TOWN`/`HW_LANE` and the `makeVehicle` timers in `buildLife` (highway traffic; the road is `buildRealRoad`, data `GC.hw`), `HOLE_SONGS` (a hole's background song: file, volume, seconds after the fly-over; `songArm`/`songTick`), `CURVE_K`/`ZOOM_AT`/`ZOOM_MIN`/`ZOOM_MAX` (tempo bar: thumb travel to power; `curMap()`, `settings.zoom`), `CLUBS` (carry in metres, launch, spin, smash), `WOBBLE` (strike-dot wobble), `HIT_PITCH`/`HIT_VOL`/`HIT_LP` (strike sound), `HOP_K`, `FESCUE_HSL`/`FESCUE_COLS`, `SFX.gobble`/`SFX.tap` (synthesised), turkey count in `buildLife`.

**Switched off but kept.** Engine features from the removed Augusta and Alsace courses stay for reuse: swirling wind, pine straw, azaleas, stone bridges, loblolly pines, the `lush`/`dry` palettes, tiered greens, and the synthesised music engine (`musicWanted` needs `COURSE.music`, which nothing sets). The Legacy course (original 18 made-up holes) was removed; it is in git history before 2026-10-17.

## Course data pipeline and adding a course

Geodata, painted-mask layers, `build.py`/`install.py` and the steps for adding another course are in the `course-data` skill (`.claude/skills/course-data/SKILL.md`). Load it before touching `tools/course/` or the course data. Never delete `tools/course/out/`.

## Woodbine Bend reference

Woodbine Bend Golf Course, 3500 E Center Rd, Stockton IL (Jo Daviess County): Lohmann/Benkusky links-style course (~2002), par 72, open rolling farmland with native fescue, mounds, a creek, two ponds, 31 OSM bunkers. Default tees: **Gold** (6,223 yd); Black, Silver and Bronze are only markers. Holes 2 and 7 have alternate tee lengths.

Gold total 6,223; Black 6,539; Silver 5,908; Bronze 5,192 (full card in `tools/course/card.py`, from woodbinebend.com/scorecard, 2024). Sources: OpenStreetMap (ODbL; way 295902659 is the course), USGS 3DEP 1 m DEM (`IL_8County_PlusChampaign_2019_B19`), USGS lidar `IL_8County_PlusChampaign_B2_2019` (the 2025 `IL_22County_D25` set is not reachable from this machine), USDA NAIP via Microsoft Planetary Computer (`il_m_4209047_ne_15_030_20230710_20230929`, July 2023).
