## Ground rules

- **Offline rule.** Solo play must work fully offline with no CDN or third-party dependency. Everything the game needs lives in the repo and `sw.js` caches it. Only live multiplayer (public MQTT brokers), the world leaderboard and the Player ID roster (GitHub API, `raw.githubusercontent.com`) may use the network, and they must fail quietly offline. Never add an external script, font or asset: download it into `vendor/` or `fonts/` (images: `img/`, credit in `img/CREDITS.txt`; public domain or a licence that allows redistribution in a public repo) with its licence and add it to `CORE` in `sw.js` (and to `pages.yml`'s copy line if it is a new folder). Sounds are synthesised, embedded as base64, or short MP3 files in `sounds/` (the eagle screech, `sounds/eagle.mp3`, is rendered by `tools/course/eagle_sound.py`; the eagle/albatross effect is `eagleShow` in index.html) (trimmed by `tools/course/sounds_trim.py` from the raw recordings in `tools/course/sounds_raw/`; listed in `CORE` in `sw.js` and copied by `pages.yml`).
- **Units.** The UI shows yards (feet on and around the green, mph for wind and ball speed). The engine works in metres. `CLUBS[].carry` is in metres.
- **`on_course_objects_and_sounds.txt`** (repo root) lists everything a player can see and hear, course by course: a GLOBAL section first (what every course has, with a table of which course has what, then the objects and then the sounds), then a section per course in picker order, each with its objects, its sounds (with frequency, rarity and condition) and its scenery. Keep it current-state only. Whenever you add, remove or retune an object (animals, planes, props, signs, buildings, markers, weather, traffic) or a sound (strikes, songs, horns, jingles, ambient), or change how often or when it appears, update that file in the same change, and delete entries for things that are gone.
- **Battery.** Phones drain fast, so the render loop is throttled by default: `frameGap()` runs the scene at `REST_FPS` (30) on the title screen, while standing over the ball and once a holed ball has dropped (the hole-done card and final scorecard), and at `ACTIVE_FPS` (60, never the 90/120 Hz of some screens) for the flyover, swings, flight and any touch in the last 0.7 s; after `IDLE_AFTER` (10 s) at rest with no touch, counted from the later of the last touch and the last full-speed frame (`UI.liveT`), it drops to `IDLE_FPS` (20); the distant woods are thinned (`FAR_THIN`, `farKeep` in `buildRealTrees`: from 70 m outside the hole a falling share of the mapped trees is drawn, down to 30 % at 330 m, the survivors' crowns widened to cover the same ground; the trees left out still stop the ball); the shadow map redraws only when its view moves or, checked at most every 0.1 s, when a shadow caster has moved (`shadowMap.autoUpdate = false`, `shadowSig`: standing over the ball with nothing walking about it is not redrawn at all), anything built from many pieces that share a material is one draw call (the clouds are one instanced mesh, `syncClouds`, its puffs re-sent to the GPU four times a second, `W.cloudT`; the side roads, cart-path crossings and all water sheets are merged, `mergeGeos`; the houses, `mergeParts`), so a course stays near 40 draw calls, the scene is not redrawn at all while a sheet is open and nothing in it is moving (`sceneStill`; the last frame stays on screen), the cards and tags over the moving scene have no backdrop blur (a stronger tint instead; sheets keep theirs), only the ground within `CUP_PATCH` (5 m) of a cup uses the terrain material with the cup's `discard`, the renderer's pixel ratio is capped at 1.5, the scene's target is 2x multisampled, the tilt-shift blur takes 16 reads a pixel, the flag cloth updates at most 30 times a second, (shadows: the shadow camera moves in whole pixels of the 2048 map, `SUN_X`/`SUN_Y`, so shadows do not shimmer as the view moves; a flag's shadow comes from a still copy of the cloth and a wider stick, `SHADOW_ONLY`, `STICK_SHADOW_R`, so it does not jump or break up) and the three HUD canvases redraw at 15 fps at rest (10 fps while the ball is away). Keep new per-frame work inside those limits.
- **Git.** Commit and push only when the user asks. `git add -A` skips each course's `tools/course/courses/<key>/out/` (ignored), so add paths explicitly and check `git status` after a commit. One commit usually covers `index.html` plus the tools, because they can't be split.
- **The painted masks are not in git.** Each course's `tools/course/courses/<key>/out/` and `.cache/` are git-ignored (as is `tools/course/sounds_raw/`), so the user's hand-painted masks (`*_mask.png`, `signs.txt`) and every generated JSON live only on this machine. The game does not need them to run (their results are in `courses/<key>.js`), but they are the source of truth for the course data. Never delete a course's `out/`; tell the user if you change how they are used.

## Working with index.html

`index.html` is the whole game engine and UI: HTML, CSS and JS in one file (about 7,800 lines, 0.75 MB), no build step. Two lines are huge embedded data, static: `SND_B64` (base64 MP3) and `CLUB_SPR` (base64 WebP); never print them whole, use `cut -c1-200`. The course data lives beside it in `courses/` (see **Courses**).

- Edit with small Python scripts that assert each `old` string matches exactly once. Line numbers drift constantly: find things with `grep -n` on the function or constant name. Code is organised under `/* ===== NAME ===== */` banners: UTIL, PHYSICS, REAL COURSE, WORLD (three.js), GAME, UI, STATS + RECORDS, PLAYER + LEADERBOARD, INPUT + LOOP.
- Python offsets are code points but JS/node offsets are UTF-16, and the file contains non-BMP characters. Never apply node-computed offsets from Python; do the splice in node or work by string match.
- **Check JS** after every edit: write the text between the last `<script>` and its `</script>` to a scratch file (`s[s.rfind('<script>')+8 : s.find('</script>', s.rfind('<script>'))]` in Python) and run `node --check` on it. For unused or undefined names, run ESLint (`no-undef`, `no-unused-vars`) on that same file from a scratch folder.
- **Browser testing (WSL, no system browser).** In a scratch folder: `npm i playwright@1.48.2 && npx playwright install chromium`; Chromium lacks `libnss3`, `libnspr4`, `libasound2t64` and there is no sudo, so `apt-get download` them, `dpkg-deb -x <deb> <dir>`, and run node with `LD_LIBRARY_PATH=<dir>/usr/lib/x86_64-linux-gnu`. Serve the repo with `python3 -m http.server` and launch with `--use-gl=swiftshader --enable-unsafe-swiftshader --no-sandbox`. Fill `#nameIn`, click `#btnPlay`, then drive the game through globals (`startHole(i)`, `G`, `W`, `impact()`, `simulateShot()`; overriding `updateCamera = () => {...}` gives a fixed camera for screenshots). Swiftshader is slow, so game time runs well under real time. There is no test suite; "tested" means all 18 holes load with every tee and cup in bounds, a shot plays, and the page logs no errors (MQTT WebSocket errors are expected offline).
- `.github/workflows/pages.yml` deploys on push to `main`: copies `index.html manifest.webmanifest sw.js *.png icon.svg vendor fonts`, replaces `__BUILD__` with the commit SHA in `index.html` and `sw.js`, writes `version.txt` (the running game reloads itself when it changes: checked on load, when the app comes back to the foreground and at the start of every round (`newBuild`, `startRound`: a newer build reloads the page and the round starts on the next tap; offline or slower than 1.5 s it just starts). `sw.js` is network-first for the page (cache after 4 s), cache-first otherwise, cache name `galena-<BUILD>`; it needs https or localhost. `tools/pages_hashes.py` stamps `sw.js` with a hash per file at deploy, so a new build copies unchanged files from the old cache and downloads only what changed; a failed install keeps what it got.
- `.github/workflows/leaderboard.yml`: registered players post scores as issues titled `[score] ...` whose JSON body is `{msg, sig, key}` (the round, signed by a device key); the workflow checks the signature against `players.json`, validates the round and its 18 per-hole rows, appends to `leaderboard/<course>.json` (the best 500 rounds plus every round of the last 46 days; the game shows the top 40 plus anyone tied with 40th for "All time" or "Last 45 days"; equal to-par scores share a rank, shown T4, T4, then 6; after a registered player's round posts, the "Round posted" pill says "You're #4 on the leaderboard" (`worldPlace`, T4 when tied); a round is its player ID and time, so equal scores are fine; at most 15 rounds a day per player) `rounds/<id>/<year>.json` (every round of that player with its per-hole data, one small file per UTC year) and `stats/<id>.json` (their lifetime summary: per course the rounds, best round and per-hole running totals, a constant size; `tools/players/stats.py` rebuilds it from the year files, splits any flat `rounds/<id>.json`, and with `--backfill` files the leaderboard rounds a player's year files lack, with `hs: null` because they were played before per-hole data; such a round counts as a round and for the best round only), and closes the issue only once its round is pushed (a failed push leaves it open). Each run also files every other open `[score]` issue, since GitHub cancels a run that waits behind another when a newer one queues; a duplicate is closed as already filed, and rounds on `alpha` or `hidden` courses are refused. It reads the courses from `courses/courses.json` (the pars per hole give the round's par; records count from the course's `recFrom` day). **Records** belong to the account, per course, and count only for a registered player's full 18-hole round (nothing from practice, nothing per device). The signed round (message version 3) carries `x` = `{d: drive, h: holed shot, p: holed putt}`, each `[decimetres, hole]`, plus `l` = the round's lipped-out putts (a count: putts with a `lip` event that did not drop), collected in `G.xr` by `statsShot` (saved with the round) and plausibility-checked by the workflow; the other records (fewest and most putts, best nine, birdies, greens, fairways and their streaks within a round) are worked out from the 18 hole rows (`roundMarks` in index.html, the same rules in the workflow and in `tools/players/stats.py`). The workflow keeps each player's bests in `stats/<id>.json` (`courses.<c>.rec`: key -> `[value, hole, at]`) and the top 5 players of each in `records/<course>.json`; `stats.py` rebuilds both (only rounds from the course's `recFrom` in `courses/courses.json` on, `REC_FROM`). The Stats sheet shows my bests beside the world's (`recs`, `loadRecords`), the leaderboard sheet has a Rounds | Records switch (`fillRecords`: every record of the course with its holder, a tap opens the top 5), `recWatch`/`recNoticeFlush` show a "Record beaten" card at the title screen when someone takes a record I held (the title screen's thin Global leaderboard button opens `#glb`: the top 3 all-time rounds of every non-alpha course that has any, from each course's world board, `glbOpen`/`glbFill`; a tap on a course opens its full board, `openBoard(key)`) (the ones I hold are remembered in localStorage `ssg-recheld`), and `recCheck` shows New personal / world record cards when a round ends. During the round `recLive` (after each shot and hole) shows a "World / Personal record pace" card, once per record per round (`G.rl`), when a mark that can only grow (drive, holed shot, holed putt, lip-outs, birdies, greens, fairways, most putts, the three streaks) passes the world's or my record; fewest putts and best nine wait for `recCheck`. Nothing counts until the round is posted. A course that nobody has posted a round on yet has no `leaderboard/<key>.json` or `records/<key>.json`; the game shows an empty board and no records, and the workflow creates both with the first round. Score posting points at `GH_REPO`; `GH_POST_KEY` holds an embedded post-only token (obfuscated) so scores post without a GitHub account (the signature, not the token, says who posted). `_original/` (git-ignored) is an untouched copy of the fork, for reference.
- **Player ID** (`PID`, `pidInit`/`pidSync`/`signRound` in index.html, just above `postAuto`; roster `players.json` at the repo root; admin tool `tools/players/players.py`). `players.json` is `[{id: "P007", name, keys: [{k, label}]}]`, written only by the admin. Each device makes its own ECDSA P-256 key pair on first use (private JWK in localStorage `ssg-pid`; never leaves the device) and files an ID request as a `[register]` issue (Settings > Player ID > Request ID; Copy ID request gives a `GG1-...` code as a spare); the admin approves it in GitHub (Actions > Approve player, `approve.yml`, run by hand with the issue number and `new` or an existing ID, so only repo writers can) or with `players.py pending|approve`, and uses `players.py add|device|drop|rename` for the rest. A device whose public key is in the roster is registered (`isReg()`): its name is the roster's, its rounds are signed and posted, per-hole history (the filed `stats/<id>.json` plus this device's newer unfiled rounds from `ssg-hist`) is shown on the Hole by hole page (Stats > Hole by hole: a bar chart of the last 45 round totals against par from `rounds/<id>/<year>.json`, then per hole par, length, best, average and an eagle / birdie / par / bogey / double split bar from the summary's per-hole stroke histogram; `holeAgg`, `openHoles` in index.html). Any other device is a guest: solo play and local stats only, nothing posted. The game reads `players.json` from raw.githubusercontent.com (cached offline in `ssg-reg`); revoking a key turns that device back into a guest. Not gated yet: multiplayer rooms (still open to guests).

## Architecture

**Courses.** `courses/courses.json` (hand-written) lists the courses in picker order (full courses, then beta, then alpha; keep that when adding or promoting one): `key`, `name`, optional `card` (the name on the play screen's card, `\n` for a new line: Legends "Legends Course\nat Memphis National GC"; without it the name is split before "at Eagle Ridge" or "Golf Course"), `short`, `pars`, `recFrom` (the day its records start), a course's `short` carries its stage in brackets: "(beta)" on every course but Woodbine, ER South, ER North, Legends and Maxwelton Braes (a label only; beta courses post and keep records as normal), "(alpha)" on the disc courses; optional `blurb` (the course's description for the play page, edited by hand in `course_descriptions.txt` at the repo root and copied into courses.json by `tools/course_text.py`, which `pages.yml` also runs on every deploy; a joke about the course for the play page, shown as plain floating text between the course tile and the picker: `playBlurbFill`, `fitBlurb` shrinks it until it fits with no scroll), optional `noTrip: true` (Augusta: the play page shows only the description, no rounds line and no "Trip champs" line) and `trip` (`{n, years, win: [[name, [years]]]}`: how many rounds the friends' annual trip has played there, in which years, and the trip champion of each of those years; worked out from the group's trip spreadsheet, whose green "Winner" cell in a year's second round names that year's champion; the disc course has no `win`), optional `music` (the synthesised background piece: `true` on the whole course, or a list of holes from 1, Augusta `[1]`; `musicWanted`), optional `only` (`true` = any registered player, a list of player IDs = only those; only they can start a round or practice there, `courseOpen`; everyone else sees it in the picker and gets a "Registered players only" or "Not open yet" note; a client-side gate, the data is public; Augusta: `true`), optional `hidden: true` (switched off: `courseList` skips it, so it is not listed, loaded or cached by `sw.js`; its data and files stay, and removing the flag brings it back: both disc golf courses since 2026-11-11), optional `alpha` (a course still being built: the game keeps nothing of its rounds: no post, no best score, stats, history, local or shared board and no record cards, so nothing is waiting to post when the course is promoted; `finishRound`, `statsShot`, `statsHole`, `postAuto`, `postWithStatus`, `recCheck`; the round in progress is still saved so it can be resumed; the disc courses and the four newest golf courses are alpha), `about` (the help sheet's course text), `engine` (merged into its `RDS` entry: `fescue`, `longRough` (the deep rough drawn as dark green long rough instead of golden fescue: ER South and ER North; Woodbine keeps the fescue), `z0`, the class grid `gr`, optional `lush`/`dry`/`tiers`/`tweak` (`dry`: the high-desert palette, golden deep rough and olive mown grass, used by Fossil Trace), `firstCut` and `fringe` (per-course overrides of the global `FIRST_CUT` and `FRINGE_W`; no course sets them: every green on every course has a 0.9 m (3 ft) fringe (`fringeW`, `FR_W` in `surfInfo`, uniform `frW` in the terrain shader), then a 1 m collar of fairway-height grass (`COLLAR_W`, folded into the fairway field in `makeRealCourse`), then rough; the first cut is a 2.8 m band beside the fairways only, none round tee boxes or greens and none within 8 m of a green, so it runs up the fairway and stops at the collar (`FIRST_CUT` `[fair, tee, green, clear]`, `firstCutW`)), `bunkerFix` (default on for every course, `false` opts out: each bunker is dug after the lidar relief, and only by what the relief does not already hold, with the 16 cm bunker lip kept off the green and its collar; before 2026-11-13 every bunker was dug twice, the engine's .45-.9 m on top of the real hollow the relief carries, so a median bunker was far deeper than the lidar's (Augusta 1.3 m against 0.57 m, Woodbine 0.97 against 0.38) and green cells beside a bunker got a lip that read 5-8 % grade; where the terrain holds no hollow the dig is the engine's full depth as before), `alt` (the course's ground height in metres above sea level, the mean of its 1 m terrain model: **every course needs one**, see Ball flight), and `disc` for a disc golf course) and `scene`, the course's own scenery (hole numbers from 1; anything left out is off): `clubhouse` (`minArea`, `front`, `sign` lines), `parkedCarts`, `turkeys` (chance a hole has the flock), `bannerPlane` and `groundhog` (the banner plane and the gopher: Woodbine and both Eagle Ridge courses), `deer` (chance a hole has deer, `makeDeer`), `bear` (Fossil Trace only: a black bear, 1.2x size, crosses the fairway 75 yd out on par 4/5 holes with the moving cart's chance `CARTRIDE_P`; `makeBear`, `bearRoute`, `bearGo`; `?bear` forces it), `squirrels` (how many per hole, `makeSquirrel`), `cornCob` (ER North only: `{hole, enu: [e, n], rx, ry}`, an ellipse in the course's local metres painted as `#FF8080` on the all-in-one map (read by hand, no reader script); a ball at rest in it, once the camera is at the next spot, sets off the giant corn cob: `cornCheck` in `finishShot`, `cornGo` in `enterAddress`, `makeCob`), Augusta's own landmarks (`clubhouse` with `style: 'augusta'` and `at`, the building picked by its place rather than its size; `cabins`, `bldColors`, `founders`, `leaderboard`, `birds` (Augusta's own four birdsong clips, sounds/augbird1-4.mp3, instead of the generic five: `{gain, pause}`, `AUG_BIRD_POOL`, `birdTick`), `crowd` (the synthesised crowd: murmur, applause or roar by a dice roll, gasps, groans, far roars; `crowdAfterShot`, `crowdTick`, `CROWD`), `dressing` (the Masters week dressing: TV towers, on-course boards, grandstands, ropes, patrons; `buildDressingANGC`): `buildClubhouseANGC`, `buildCabinANGC`, `buildIkeCabin`, `buildButlerCabin`, `buildGroundsANGC`, `buildLeaderBoard`; its plants are hand-placed tree kinds 5 and 9-26 from `SPECIMENS` in its course.py, `tools/course/pines.py`, drawn by `buildRealTrees`/`NAMESAKE_LOOK`), `houses` (Legends: every building but the clubhouse, the `keep` list (cart barns, by centroid) and anything under `minArea` (100 m2) is drawn as a Memphis-suburb house, `houseSpec`/`houseParts`), `cartRide`, `hotdogHole`, `fountainHole`, `songs` (per hole: `src`, `vol`, `delay`) (steady traffic on a named road is not a scene key: the course's `TRAFFIC` in course.py becomes `roadBusy` in its data, see the `course-data` skill). The engine reads it through `RDC.scene` (the course whose data is in play). Everything else that lives on the course (balloon, birds, weather, farts) is the same on every course. Each course's data is `courses/<key>.js` (`COURSE_DATA.<key>.rd` and `.alti`, ~430 KB), **written by `tools/course/install.py`, never edit by hand, never print whole**. The game fetches the list before `boot` (`courseInit`) and loads a course's data the first time it is needed (`courseLoad`, `withCourse`; `COURSES[k].defs` is null until then, so code that only needs the pars uses `COURSES[k].pars`); `sw.js` keeps every listed course for offline play and `pages.yml` copies `courses/`. The course picker is a native dropdown (`select.courseSel`: `#selCourse` on the play screen, `#selCourseP` on the Practice sheet above the hole grid, one option per course's `short` name; the Practice one only lists that course's holes (`pracKey`, `pracFill`) and switches course when a hole is tapped (`pracHole`, which keeps a round in progress)), built from the list and shown once there are two courses. The practice green and the driving range are `PRACTICE_COURSE`'s (Woodbine) whichever course is picked: `courseFor` switches the data in (`useRealData`) for them and back for the holes. **Settings sheet** (`syncMenu`): from the title it shows only Stats, Leaderboard and How to swing above the settings; in a round Replay, Restart round and Abandon round (red, `.mbtn.danger`), Save and quit, Stats, Leaderboard, Scorecard, How to swing; in practice New round as well. Players online is at the top of the sheet; the game joins the broker at launch and subscribes to every course's lobby, so it lists anyone in a round even from the title screen. Alpha courses fetch no board or records file (`loadWorld`, `loadRecords`). **Start screens:** the title screen (`#title`: player name, Tee off, Practice, Settings) opens the play screen (`#play`: back, the course picker, Continue round (`btnResume`, shown when a round is saved) and New round (`btnNew`); leagues and tournaments will be added here). The title shows no course name; the game opens on the course of the most recent saved round, else Woodbine (`courseStartKey`). Anything that starts a round or practice hides both with `titleOff()`. Per-course storage keys (`ssg-best-<key>`, `ssg-board-<key>`, the saved round), the multiplayer lobby, the pin sheet and the leaderboard and records files are all keyed by course.

**Data to game.** `tools/course/` (Python) turns public geodata into one data object per course, which `install.py` writes to `courses/<key>.js`. At run time: `setCourse` (`COURSES`, `RDS`) selects it; `realPrep` decodes the course-wide data once (`GC`); `makeRealCourse(idx, pin)` builds one hole as a lattice of fields (fairway, green, tee, sand, water, creek, fescue distance fields) plus the ground height, dug greens, ponds, bunkers and creek pieces, and returns the `C` object the whole game uses (`C.surf`, `C.h`, `C.wl`, `C.cup`, `C.treeHit`); `buildRealHole` makes the three.js scene (terrain shader, trees, buildings, props, wildlife). The LiDAR relief layer (mounds) is added over the whole ground except on greens (`GM` mask in `makeRealCourse`): each green already carries the real contours, and counting them twice made hole 7 average a 9 % grade (a ball never slows above `mu` = 5.6 %). **Woodbine Bend is the standard every course is held to** (sizes, green slopes, tuning): no green on any course may be steeper than Woodbine's steepest, its 90th-percentile grade over `GREEN_P90_MAX` (4.4 %, just over Woodbine hole 5's 4.39 %) or its mean over `GREEN_MEAN_MAX` (3.3 %, just over hole 17's 3.26 %), measured on the finished surface with its roll; a steeper green keeps its contours and loses just enough of its overall tilt (`platform` in `makeRealCourse`; no Woodbine green reaches either limit, so Woodbine is unchanged). Eagle Ridge South's greens 2, 4, 9, 10, 12, 13 and 18 are trimmed this way (18 keeps 43 % of its tilt); Eagle Ridge North's are all but 5, 6, 11 and 16 (8 keeps 46 %); Stonehenge's 3, 5 and 16 (5 keeps 37 %). Where a green's contours alone are over the limit with all its tilt gone (Fossil Trace's 5, 7, 9, 11, 12, 14 and 18), the contours are scaled down too (`platform`: `kk`); no other course is touched. The engine settings that would move a course's greens off the standard (`greenK`, `tiers`, `tierCut`) are set on no course, and `courseReady` warns in the console if one is. **Tee boxes face their holes** (every course, since 2026-11-13): `build.py`'s `face_tees` turns each tee box so it runs straight down the start of its fairway (par 3: at the green) and the game's tee markers stand square to the same line (`teeFacing`; on a par 3 the day's cup); see the `course-data` skill. Surface class is decided in `surfInfo` in a fixed precedence (water, sand, green, fringe, tee, path, fairway, first cut, pine straw, deep, rough); the tall fescue is the only `DEEP`. Pine straw (`S.STRAW`, only where a course's data has `straw`: Augusta) is a lie of its own between rough and deep rough: a full 7-iron carries about 90 % of a fairway one (rough 95 %, deep rough 88 %) with less spin and a wider spread, and a ball landing on it stops dead (a 7-iron rolls 1.6 yd, 4.4 in rough). The green slope test is `tools/green_slope_test.js` (the finished surface's grade over each green's cells; run it on a new course beside Woodbine's, which reads 3.34 % mean / 4.46 % p90 at hole 17 by it). Augusta's greens, after `bunkerFix`, read 2.0-3.3 % mean and 3.1-4.9 % p90 (before: up to 4.0 % and 8.1 %); the steep cells left are the 1-2 m strips where a green falls into a bunker or Rae's Creek (holes 1, 7, 12). Water is judged by the water level over the ground: inside the painted outline anything 2 cm under counts, outside it (the dug banks dip below the water line) a ball is wet once the water covers half of the drawn ball (`WET_HALF`), so a ball visibly in the water is never a playable lie. Everything outside the hand-painted boundary is out of bounds, and so is anything inside a hole in it (`GC.obIn`: the boundary polygon's inner rings; only Adler Park has one, its fenced pool).

**Ball and cup size.** The ball (`VIS_R` 0.055 m) and cup (`CUP_VIS_R` 0.16 m, a 12.6 in hole) are ~2.6x and ~3x real size (the cup a little wider than the real proportion, since the ball looked too big for it at 0.14 m), with gravity over the hole scaled by `CUP_G` (x.7). Chosen 2026-10-27 from a make-rate study (aim sd 1.2°, pace sd 18%, fitted to tour make rates; putts on the real greens): at 0.14 m, 3/5/8/10/15/20/30 ft holed 99/93/78/67/41/31/19 % (tour 96/77/50/40/23/15/7; the old 0.28 m cup gave 100/98/92/84/66/52/36); widened to 0.16 m the same day for looks, not re-measured, so a little higher. The flagstick (`PIN_R`, 0.0175 m) is scaled with them: the gap between stick and wall must stay wider than the ball, or nothing drops with the flag in. Changing any of these sizes changes how many putts and chips drop. These sizes are global constants, the same on every course: nothing in `courses/courses.json` or a course's data can change them, and a new course never gets its own.

**Ball flight.** `simulateShot(C, o)` is a fixed-step simulation (drag, lift and spin fitted to TrackMan data; surface bounce, roll, trees, buildings, cup). `calibrateClubs()` solves each club's ball speed at start-up so a full swing on flat ground carries exactly `CLUBS[].carry`; `launch` and `spin` shape the flight and roll, `smash` only sets the displayed clubhead speed. `impact()` turns the swing (`SW`: tempo, strike dot) into a launch, runs the simulation, and `updateFlight(dt)` plays the recorded frames back with the camera (`camFollowTargets`), trail, particles and slow-motion. A wedge swung short launches higher (`clubLaunch`, `PARTIAL_LOFT`: the lob wedge 33.5° at full power, about 41° at half, 46° at a quarter; every other iron and wedge less in proportion to its loft (`clubLaunch`: none for woods and hybrids, a mid iron about 2° at half power); out of sand `SAND_WEDGE_LOFT` more again). **Out of a bunker** a swing carries a share of its fairway carry that falls smoothly with the club's loft (`SAND_F`, `sandF`, `sandDist`: 90 % for the sand and lob wedges at 56 degrees and up, 83 % for a pitching wedge, 72 % for a 7 iron, 65 % for a hybrid, 62 % for the woods at 18 degrees and under, the driver a tenth less again off the grass), at every swing power (`lieCal` is calibrated for sand as for rough and straw), so the long-to-short carries fall steadily and the Lie chip after the shot shows the share; before 2026-11-13 wedges lost 10 % and every other club about half, so a pitching wedge out-carried a 9 iron, and the carry tables use the same launch, so the aim ring is still the true carry. A pure, full-speed, well-timed strike with a sand or lob wedge (`pure` in `computeLaunch`; `WEDGE_SPIN`) carries `biteSpin`, extra spin used only at the first landing (`o.bs` in `simulateShot`), so it checks and backs up a few yards on a green while the flight and the calibrated carry stay as they are; a tailwind removes the spin-back (`TAIL_NO_BACKSPIN`). **Distances on screen** are what a pure swing carries from the lie the ball is in: the HUD and the aim ring use `predictCarry` (real ground and lie); the tempo bar's tick labels and live readout use `shownCarry` and the bag sheet `lieCarryOf`, both built on `lieTable` (`computeLaunch` at each power from the current surface, kept in `LIE_TAB`, scaled so the club in hand's full swing reads `G.carry`), so a bunker, rough, straw or a driver off the grass shows its own numbers, while a tee shot or fairway iron still reads the fairway table (`CLUBS[].table`, `carryForPower`, which the chip-line search still uses). **Altitude** (`engine.alt` per course; `AIR_K`, `airK`, `setAltitude`, `ALT_REF_M`): drag and lift scale with air density, which follows the standard atmosphere with height, so a course above the reference carries farther (`KAERO * AIR_K` in `simulateShot` and `flatCarry`, `DISC_KD * AIR_K` for discs). The reference is Woodbine Bend's 250 m (the standard every course is held to), so Woodbine plays exactly as before and `CLUBS[].carry` means the carry at 250 m; `calibrateClubs`/`calibrateDiscs` solve each club's ball speed at the reference air once (`carry0`), and `clubTables`/`discTables` redo the carry tables, totals, rough-lie factors and `CLUBS[].carry` whenever a course with a different altitude is switched in (`useRealData` -> `setAltitude`; the practice green and range take Woodbine's). Fossil Trace (1,775 m) carries about 6-8 % farther (driver 229 -> 241 m); ER South/North/General, Stonehenge, Thunderhawk, Bear Slide and the disc courses within 1 %. Weather has no effect on it, and the tables are always measured in the dry calm conditions of start-up. The "Dramatic bounce" setting (`drama()`, `HOP_K`, `BALL_CAP`) only changes how the flight is drawn, never the physics.

**Putting read** (every putt on every golf course and the practice green; `slopeShow` is the one switch). Faint dark contour lines every 6 cm of rise and a grid of `SG_CELL` (1.25 m) squares (unmarked) drawn in the terrain shader (`slopeGrid` in `TERRAIN_GLSL`), each square with two rows of three small dots flowing downhill across it, like PGA Tour 2K's grid, so it takes one read per green pixel of `tSlope` (`slopeGridBake`: one texel per square, baked the first time a hole's green is putted on, sized from the green's real extent). A steeper square's dots run much faster (with the steepness to the power 1.5: about 0.1 m/s at 1 %, 0.4 at 3.5 %, 0.6 at 5 %) and turn from pure white to a bright reddish pink (unlit: laid over the lit result, `sgC`/`sgA`, so the low orange sun and shadows do not dull them), and the squares near the aim line are brighter. `#puttRead` is the chip above the strike tile (`puttReadFill`: graded words only, no distances, so it does not give the putt away: slightly, plain or steeply uphill or downhill by how much the slope changes the pace, then Straight, Slight break, Breaks or Big break, left or right, from one simulated pure putt at the hole, per ball and cup). While a putt is read or rolling, the tilt-shift's sharp band stretches from the ball to the target (`renderTiltShift`). A putt's path stays on the green as a gold line until the next stroke (`puttLineShow`, `puttLineClear`). The map sheet's Slope view (`drawGreenRead`, `mapRead`; the default for a putt on the course, a button on the practice green, where the map still places the ball) shows the green from above with the putt pointing up the screen, shaded by steepness, with contours and downhill marks. `#puttLift` (Hold to look down; `LIFT`, `liftCam`) raises the camera over the putt while held.

**Practice green.** A scene beside the 18 holes (`RD.prac`, `PRAC`/`PRAC_DEF`, `makeRealCourse(PRAC)`; data from `tools/course/practice_read.py`, see the `course-data` skill), reached from the Practice menu (`startPuttingGreen`, `G.pg`, `body.pg`). It has four cups (`C.cups`; `C.cup` is the one aimed at; `simulateShot` judges the ball against the nearest, `res.cup` is the one it fell in), all four flags stay up, and a close map (`C.planBox`) on which a tap puts the ball down (`mapPick`). `pgFinish` replaces `finishShot` there: every putt or chip counts, a holed ball is set 2 ft from its cup, `#pgBar` offers the cup to aim at and Redo (back to where the last shot was played from). The counter is for the session only; nothing is scored, saved or awarded (`finishShot` returns to `pgFinish` before `statsShot`).

**Driving range.** A second practice scene (`RD.drv`, `RANGE`/`RANGE_DEF`, `makeRealCourse(RANGE)`; data from `tools/course/range_read.py`, mask `courses/woodbine/out/range_mask.png` painted over `range_edit.py`'s `range_edit.png`/`range_start.png`: green mown grass, cyan target greens, magenta fescue, orange bunkers, blue dots hitting spots, red dots flags, yellow circles trees, azure `#0080FF` the metal shed). It rides on the practice-green plumbing: `G.pg` with `range: true` (`startPuttingGreen(true)`, `body.pg` + `body.rg`, `#pgBar`: the Flag button is `pgCup`, the Spot button is `pgRe`). The painted features and boundary live only in `RD.drv.feat`/`.boundary` (`rangeScene`), never in the course-wide `feat`, so no hole sees them; the shed is a `shed` row appended to `props`. Flags are `C.cups` with `C.noCup = true` (no hole, no holing, taller poles); `rgAim` aims at the chosen flag without touching the club, `rgPlace` stands on a spot (teed unless in sand), `rgFinish` shows carry/total/to-flag, rests the camera ~1.4 s, then `rgPlace` + `settle` bring it back (no early arrival move: `canPre` is off on the range). A spot on unpainted ground gets 5 m of mown grass and is kept in bounds by `range_read.py`.

**Disc golf.** A course whose `engine` sets `disc` (CMDG) is played with discs: `useRealData` calls `setBag`, which swaps the contents of `CLUBS` for `DISC_BAG` (distance driver, fairway driver, midrange, putter: `speed`/`gl`/`turn`/`fade` flight numbers, `carry` a clean full throw on flat ground; `PUTTER` is the last item either way) and the ball mesh for a disc (`discLook`, `BALL_LIFT`); the practice green and range stay golf. `computeLaunch` hands a disc to `discLaunch` (tempo and power as a swing; the strike dot across sets the release angle, hyzer on the toe side, anhyzer on the heel side; up and down the nose; `discRelease` releases a soft throw flatter so a putt arrives at basket height) and `simulateShot` hands `o.disc` to `simulateDisc` (lift and drag after Hummel's frisbee model, `DISC_*`; the turn rating rolls the disc over near full speed, the fade rolls it back as it slows; trees knock it down or let it through; it skips and slides on landing, `DISC_GROUND`; `res.att` is its bank per frame, drawn by `discPose`). The basket (`buildBasket`, in `buildCup`'s place; `BASKET_K` 1.3x real size): a disc whose centre passes inside the chains (`BASKET_R`, between `BASKET_LO` and `BASKET_HI`) slower than `DISC_CATCH_V` is caught (`res.holed`, event `chains`); faster it is spat out (`spit`); the tray, band and pole knock it down (`cage`). `calibrateDiscs` solves each disc's release speed and power table; the caddie (`autoDiscAndAim`) picks the shortest disc that reaches and aims at the basket, and the power line (`discChip`) is the power that brings a clean throw to the middle of the chains. With PALS Rules a disc at rest inside `DISC_DROP` (1 m) is a drop-in. These sizes are disc-golf constants, separate from the golf ball and cup. The course data has no greens (`GREEN_ALTI` is empty; `makeRealCourse` puts the cup, and so the basket, on the hole's `green` point) and comes from `tools/course/disc_build.py` (see the `course-data` skill). Records, leaderboard and stats work as for golf (par 3 holes), but CMDG and ADGC are `alpha`, so nothing is posted. ADGC has one tee per hole, so its holes 10-18 repeat 1-9 from the same tees.

**PALS Rules** (Settings, on by default since v1.0; `palsV` 3 switched every device on once, `pals()`): house rules, so far the **mulligan**: one per nine holes (`G.mull`, use it or lose it), taken at address on the shot just played (`mulliganOk`, `mulligan`; not after holing out; a penalty stroke goes with it). `impact` snapshots the state (`G.snap`: strokes, putts, flags, the round's shot records, the stats counters, the lie, club and aim) and a mulligan restores it; the button sits over the tempo bar and needs a second tap. The signed round carries `mu` (1-2, only when taken), the workflow keeps it on the leaderboard row and the board shows "mulligan". Rounds with mulligans stay on the board and count for records. The **maximum hole score** (`maxScore(par)`): par + 5 normally, double par + 1 with PALS Rules on (par 3: 7, par 4: 9, par 5: 11); a hole that reaches it is picked up. The **gimme**: a ball at rest on the green or fringe inside 24 in (`GIMME_M`) of the edge of the drawn hole (the cup is drawn 12.6 in across), and always anything the readout shows as 2 ft or less (`GIMME_D`, measured from the centre: 30 in), is conceded in `finishShot`: one stroke and one putt are added, the hole ends, and a brown "Inside the rope!" card (`gimmeCard`, `gimmeRope`: an SVG of a 22 in length of teal, yellow and red braided rope, to scale) shows. Not recorded in the signed round.

**Weather** follows the clock, per course (`wxClock(key, ms)`: smooth noise seeded by the course key, `WX_CELL` 90 min, bands `WX_TH` give dry 30 / fine 35 / damp 20 / rain 15 %), so every player on a course sees the same sky at the same moment, in solo, practice and multiplayer; a hole takes the weather of the moment it starts (`beginHole`), and nothing is stored or sent. It changes only the bounce and roll on the ground (`WX_GROUND`: tee, fairway, first cut, rough, deep rough, fringe, green, sand; `setWeather` -> `SURF_WX`), by the same factors on each; the putting power line (`computeLaunch`), `puttEquiv` and the cup read `SURF_WX` too, so they follow it; cart paths and the flight are unaffected. Events and tournaments will define their own weather and pins per round (creator-set, not built yet). The device clock is trusted.

**Round state.** `G` holds the round (scores, putts, `G.pins`, weather); `saveRound` persists it per course (after every shot, when the app is hidden or closed; one round per course, kept 30 days, never overwritten by an empty one; the play screen's Continue round brings it back). **Leaving a round:** Settings > Save and quit (`quitToMain(true)`) keeps it; Settings > Abandon round (a confirmation, then `quitToMain(false)`) deletes it, and holes already finished stay in the lifetime stats (`statsHole` counts each hole as it is finished; a round counts, sets a best and posts only when all 18 are done); the finished round's scorecard Main menu clears it as before. Practice, the practice green and the driving range never touch a saved round (starting one in the middle of a round saves it first, `startPractice`/`startPuttingGreen`; leaving practice keeps it), and New round (the play screen's button or Settings' when a round is saved on the course, `newRoundAsk`) asks first (Continue round, Start a new round, Cancel); Restart round has its own confirmation. **Round state.** `G` holds the round (scores, putts, `G.pins`, weather); `saveRound` persists it per course; each round takes the day's pin (0-3: front, back, right, left, as seen on the way in) per hole from `pinSheet()` (**Augusta** instead plays the club's own four hole-location sheets, the 2026 Masters rounds 1-4 read off the published sheets into `courses/augusta/pins.json` by `tools/course/masters_pins.py` (data `holes[].pins`: share of the green's depth from the front, place between the left and right edges, so it fits this green's outline); one sheet a day on every hole, stepping Thursday (round 1) to Sunday (round 4) and round again at the pin day's roll-over, anchored on 2026-04-09 = round 1: `pinRound`; practice walks the four) otherwise: a hash of the pin day (Central time, rolls over at 5:00 AM), the course, the private room code (or `open` for solo and the public lobby) and the hole, so everyone in the same lobby plays the same pins. A round keeps its pins once started; practice still draws random pins.

**Tunables worth knowing:** `HW_FAST`/`HW_TOWN`/`HW_LANE` and the `makeVehicle` timers in `buildLife` (highway traffic; the road is `buildRealRoad`, data `GC.hw`), `scene.songs` in `courses/courses.json` (a hole's background song: file, volume, seconds after the fly-over; `holeSong`, `songArm`/`songTick`), `CURVE_K`/`ZOOM_AT`/`ZOOM_MIN`/`ZOOM_MAX` (tempo bar: thumb travel to power; `curMap()`, `settings.zoom`), `CLUBS` (carry in metres, launch, spin, smash), `WOBBLE` (strike-dot wobble), `HIT_PITCH`/`HIT_VOL`/`HIT_LP` (strike sound), `HOP_K`, `FESCUE_HSL`/`FESCUE_COLS`, `SFX.gobble`/`SFX.tap` (synthesised), turkey count in `buildLife`.

**Switched off but kept.** Engine features from the removed Augusta and Alsace courses stay for reuse: swirling wind, pine straw, azaleas, stone bridges, loblolly pines, the `lush` palette, tiered greens, and the synthesised music engine (`musicWanted` needs `COURSE.music`, which nothing sets). The Legacy course (original 18 made-up holes) was removed; it is in git history before 2026-10-17.

## Events, tournaments and seasons (foundation, admin only, not live)

Nothing here is visible to players: **Settings > Competitions** shows only to a registered player marked `"admin": true` in `players.json` (P001), and the workflow checks the same flag, so the client check is cosmetic. Terms: an **event** is one play of a **card** (1-72 holes, any mix of courses and holes), a **tournament** is a series of events between a start and an end date, a **season** is a series of tournaments. Hierarchy by `parent`: event -> tournament -> season (each optional); a child's dates must sit inside its parent's.
- **Data.** `competitions/<id>.json` (id `ev-`/`tn-`/`ss-` + 4-12 lowercase letters or digits) and the list `competitions/index.json` (`id, kind, name, start, end, parent`). An item: `name, desc, start, end` (YYYY-MM-DD), `invite` (`"open"` or player IDs), `pals` (true by default: PALS Rules in that competition, set per tournament and inherited by its events), `hcp` (`gross` or `net`; net needs the handicap data below, not live), `points` (points by finishing place), and for an event or tournament `format` (stroke, stableford, match, skins, bestball, scramble), `play` (live, batched or either), `team` (1; 2-4 for scramble and best ball); an event has `card: [{c: courseKey, h: 1-18}]`; a season has `countBest` (how many tournament results count, 0 = all). Alpha and disc courses are refused in a card. Writing: `tools/players/comp_validate.js` (the one validator, shared with the workflow) and `.github/workflows/competitions.yml` (a signed `[comp]` issue `{msg, sig, key}`, `msg` = `{v: 1, act: save|delete, pid, at, item|id}`, signed by an admin device key; stale (>1 h) requests refused so a replay cannot undo a newer save; a parent cannot be deleted while it has children, and a parent's dates must still cover its children).
- **Admin UI** (`COMPETITIONS` banner in index.html, `compSheet` list and `compForm` editor): tree of seasons > tournaments > events, tap to edit, + Season / Tournament / Event, a card builder (course, hole, front 9, back 9, all 18), Save/Delete. It posts the signed issue and polls the issue's comments for the workflow's answer. No code change is needed to make one.
- **Not built yet:** playing an event (live and batched), scoring by format, points and standings (event -> tournament -> season), their leaderboards, who may join, and any player-facing screen. Plan: results are signed per-hole rows (a new message version, since the signed round is 18 holes), pins and wind seeded by the event id like a room, live play over the existing MQTT rooms.
- **Handicap (not live).** `tools/players/handicap.py ratings` writes `handicap/ratings.json` (each course's played tee: rating, slope, par, from the `course.py` files); `handicap.py calc` reads `rounds/<id>/<year>.json` and writes `handicap/handicaps.json` per player: World Handicap System differentials (113 / slope x (adjusted gross - rating), each hole capped at par + 5), index = the best N of the last 20 (WHS table, at least 3 rounds, capped 54). The indexes come out low because the game is easier than the real courses; it needs more rounds and a decision about calibration before it is shown or used for net play. The game reads none of it.

## Course data pipeline and adding a course

Geodata, painted-mask layers, `build.py`/`install.py` and the steps for adding another course are in the `course-data` skill (`.claude/skills/course-data/SKILL.md`). Load it before touching `tools/course/` or the course data. Each course is a folder `tools/course/courses/<key>/` (`course.py` plus its git-ignored `out/` and `.cache/`); scripts take `--course <key>` (default `woodbine`). Never delete a course's `out/`.

## Woodbine Bend reference

Default tees: **Gold** (6,223 yd); Black, Silver and Bronze are only markers. Holes 2 and 7 have alternate tee lengths.
